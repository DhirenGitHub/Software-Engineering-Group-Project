# SEGP Surveillance UI

A real-time AI surveillance dashboard built with React + Vite. Displays live camera feeds with person-detection overlays powered by a local YOLO ONNX detection server.

---

## Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| Node.js | 18+ | For the React UI |
| Python | 3.10–3.11 | **3.11 recommended** — onnxruntime wheels may not exist for 3.12+ |
| pip | latest | `python -m pip install --upgrade pip` |

---

## File structure

```
UI/
├── assets/
│   ├── YOLO.pt          # Fine-tuned YOLO model (required — not included in repo if large)
│   └── YOLO.onnx        # Exported ONNX model (generated by export_onnx.py)
├── public/              # Static files served by Vite (put test videos here)
├── server/
│   ├── app.py           # Flask detection server
│   ├── detector.py      # Threaded YOLO inference classes
│   ├── export_onnx.py   # One-time ONNX export script
│   └── requirements.txt # Python dependencies
├── src/                 # React source
└── package.json
```

## Setup

### 1 — Install React dependencies

```bash
cd UI
npm install
```

### 2 — Install Python dependencies

```bash
cd UI
pip install -r server/requirements.txt
```

> If you have multiple Python versions, use the explicit binary:
> `python3.11 -m pip install -r server/requirements.txt`

### 3 — Export the ONNX model (one-time)

The detection server uses an ONNX version of the model for faster CPU inference.
Run this once after cloning — it reads `assets/YOLO.pt` and writes `assets/YOLO.onnx`.

```bash
cd UI
python server/export_onnx.py
```

You only need to re-run this if you swap the model file.

## Running

Both processes must be running at the same time. Open two terminals.

### Terminal 1 — React UI

```bash
cd UI
npm run dev
```

Open [http://localhost:5173](http://localhost:5173) in your browser.

### Terminal 2 — Detection server

```bash
cd UI
python server/app.py
```

The server starts on `http://localhost:5000`. It prints your local network IP at startup — you'll need this if adding cameras from another device on the same network.

## Adding a camera

1. Open the UI → click **System Configuration** (bottom of sidebar) → **Camera Feeds**
2. Click **Add Camera**
3. Fill in:
   - **Camera name** — display label
   - **Location label** — shown on the feed tile
   - **Source type** — choose the input type (see table below)
   - **Stream URL** — the source URL or file path

| Source type | Example URL | Notes |
|-------------|-------------|-------|
| MJPEG HTTP | `http://192.168.1.101/mjpeg` | Works with most IP cameras and MJPEG apps |
| Video File | `C:/path/to/video.mp4` | Use an absolute path; the file loops |
| HLS | `http://host/stream/index.m3u8` | Requires CORS headers on the server |
| Webcam | *(leave URL blank)* | Uses browser `getUserMedia` |
| RTSP | `rtsp://192.168.1.101/stream1` | Requires server-side proxy — not directly playable in browser |

4. Click **Save**

When the detection server is running, the camera is automatically registered and the feed switches to the annotated MJPEG stream with person-detection bounding boxes.

If the detection server is **not** running, the raw feed URL is used as a fallback (no bounding boxes).

## Detection toggle

In the dashboard sidebar under **Feed Controls**, the **AI Detection** toggle switches all camera feeds between:

- **On** — annotated MJPEG stream from the detection server (bounding boxes visible)
- **Off** — original raw feed (no processing)

## Using a phone as a camera (MJPEG app)

1. Install an MJPEG streaming app on your phone (e.g. IP Webcam on Android)
2. Connect your phone and PC to the same WiFi network
3. Start the stream in the app — note the MJPEG URL it shows (e.g. `http://192.168.0.x:8080/video`)
4. In the UI → Add Camera → Source type: **MJPEG HTTP** → paste the URL

> **iPhone note:** iOS Safari requires HTTPS for camera access via browser. Use an MJPEG app instead of the browser capture approach.

## Detection server API

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/cameras` | Register a camera `{ id, source, conf?, iou? }` |
| `GET` | `/cameras` | List registered cameras |
| `DELETE` | `/cameras/:id` | Stop and remove a camera |
| `GET` | `/video/:id` | MJPEG stream with detection overlay |
| `GET` | `/health` | Liveness check |

Example — register a video file manually:

```bash
curl -X POST http://localhost:5000/cameras \
     -H "Content-Type: application/json" \
     -d '{"id":"CAM01","source":"C:/path/to/video.mp4"}'
```

## Troubleshooting

**Black feed after adding camera**
- Check that the detection server is running (`python server/app.py`)
- Remove the camera and re-add it so registration is retried
- Make sure the source URL/path is correct and accessible from the server machine

**`FileNotFoundError: YOLO.onnx does not exist`**
- Run `python server/export_onnx.py` to generate the ONNX file

**`Cannot open source: /path/to/file.mp4`**
- Use the full absolute path (e.g. `C:/Users/you/videos/test.mp4`)
- Forward slashes work on Windows

**Detection server port already in use**
- Another process is using port 5000. Kill it or change `PORT = 5000` in `server/app.py`

**ONNX install fails / wrong Python version**
- Make sure you're installing into Python 3.10 or 3.11
- Use `python --version` to check, then `python3.11 -m pip install ...` if needed
